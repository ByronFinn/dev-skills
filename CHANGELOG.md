## [Unreleased]

### Added
- **GEPA-style evaluation framework** (`docs/evals/skills-eval.md` + `scripts/eval_skills.py` + `scripts/evals/`) — four-level eval: **S** static per-skill compliance (frontmatter, description, outcome-contract-first, line budgets, TOC for >300-line references, sub-agent chapter shape, one-by-one interview contract), **W** workflow coherence (check-docs.py + handoff graph + Traceability producer/consumer pairs + README coverage + cross-skill step-reference validity + research INDEX consistency), **T** trigger routing (deterministic IDF-weighted proxy every iteration; sub-agent T-Live rounds at checkpoints), **B** behavior simulation (turn-by-turn actor/judge protocol with scripted user answers for the interviewing skills). Every failing check emits textual feedback (GEPA's Actionable Side Information); 20-query trigger set with 60/40 train/holdout split; behavior scenarios one train + one holdout per interviewing skill. Grounded in `docs/research/gepa-eval-loop-1.md`. Iteration log + scoreboard: `docs/evals/results/` (baseline S 176/190 → 216/216 hard; T-Live 20/20; behavior defects found and fixed across 2 checkpoints).
- **Research knowledge base** (`docs/research/` + INDEX) — first three records, produced with `/research`: `agentskills-skill-authoring-1.md` (spec + official authoring/evaluation bar), `agent-interviewing-question-pacing-1.md` (one-by-one adaptive questioning: academically supported, officially unmandated — adopted as product decision), `gepa-eval-loop-1.md` (eval loop design: per-sample textual feedback, dual-sided datasets, holdout selection, budget stopping).
- **One-question-at-a-time adaptive interviewing** — `grill` reworked from the round/frontier batch model to a strict one-question-per-message walk of the decision tree: the next question is derived from the user's last answer (an answer resolves a node, opens children, or closes a branch), termination on tree exhaustion, never a pre-computed list; `think` Q&A loop gains the same contract plus a no-piggyback-riders rule (one decision per message; approval submissions ask approval only, setup questions settled beforehand as their own single questions). Evidence base and honest sourcing boundary: `docs/research/agent-interviewing-question-pacing-1.md`. Behavior verified by simulation checkpoints (see `docs/evals/results/checkpoint-1.json` / `checkpoint-2.json`).
- **Anti-patterns #3/#4 inverted to match the doctrine** — #3 "Batch interrogation" (a multi-question message or numbered list, including piggyback riders like "顺便确认…") and #4 "Pre-computed question list" (generate the list upfront instead of deriving each next question from the last answer). Numbers frozen; wording replaced; consumers re-swept.
- **TOCs for long reference files** — `review` (648→), `tdd` (546→), `think` (445→), `setup-project` (316→) REFERENCE.md files gain `## Contents` blocks (skill-creator guidance: files >300 lines need a table of contents), generated fence-aware so headings inside code templates don't pollute the list.
